# Sensación de app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the public web (`sistema-web/`) look and respond like an app without removing any screen, link, feature or data.

**Architecture:** Only shared pieces change: the landing and auth pages, `AppShell` (nav, header, page transition), plus three new client components (icons, toasts, install button). Existing `role="status"` messages stay; toasts are added next to them.

**Tech Stack:** Next.js 15 static export, React 19, Tailwind v4 + `src/styles/theme.css` tokens, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-24-app-feel-design.md`

All commands run from `sistema-web/`.

## Global Constraints

- No new npm dependencies (icons are hand-written inline SVG).
- No hardcoded person name anywhere in `sistema-web/` (e.g. "Miss Yosselin"); greeting uses the signed-in profile's `firstNames`.
- No screen, nav link, label or route is removed; existing link labels keep their exact text (tests and E2E rely on them).
- UI copy in Spanish; identifiers and commits in English (Conventional Commits).
- Colors only from theme tokens (`bg-primary`, `.card`, `.field`, `.btn-primary`, …); no `blue-*`/`gray-*` classes left in touched files.
- Animations disabled under `prefers-reduced-motion: reduce`.
- Must keep working offline (no new network requests, no external fonts/images).

## Review Focus

1. A page that calls `useToast()` rendered without `ToastProvider` (existing page tests) → must not throw; toast is a no-op. (Task 2 test)
2. Profile with empty `firstNames` → header shows just "Hola", never "Hola, " or "undefined". (Task 3 test)
3. Two saves in a row → the newer toast replaces/stacks without the old timer hiding the new one early. (Task 2 test)
4. Browser without `beforeinstallprompt` (Firefox/Safari) or app already installed (`display-mode: standalone`) → no install button. (Task 4 test)
5. Mobile nav still has ≤ 5 children after adding icons (icons go inside each link, not as siblings). (Task 3, existing test kept)
